# segmentation-biomarkers-ml

Биомаркеры по фундус снимкам.

## Форматирование и проверка кода

В проекте используется **Ruff**: `ruff format` приводит Python-код к единому
оформлению, а `ruff check` находит ошибки и проверяет порядок импортов.
Правила хранятся в `ruff.toml`. Версия Ruff одинаковая в `requirements-dev.txt`
и `.pre-commit-config.yaml`; при обновлении меняйте её в обоих файлах.

### Установка инструментов

Для инструментов разработки нужен **Python 3.11 или новее**.
Из корня репозитория создайте и активируйте окружение:

```powershell
# Windows PowerShell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

```bash
# Linux / macOS
python3.11 -m venv .venv
source .venv/bin/activate
```

Если окружение уже создано через uv или Poetry, используйте его с Python 3.11+.
Затем установите инструменты и Git-хук:

```bash
python -m pip install -r requirements-dev.txt
python -m pre_commit install
python -m pre_commit run --all-files
```

Для линтинга и форматирования не нужны PyTorch, GPU, датасет или веса модели.
Зависимости самого ML-приложения остаются в `requirements.txt`; устанавливайте их
отдельно в подходящее для них окружение. Папка `.venv` не добавляется в Git.

### Ежедневная работа

Проверить код без изменения файлов:

```bash
python -m ruff check .
python -m ruff format --check .
```

Применить безопасные автоматические исправления и форматирование:

```bash
python -m ruff check --fix .
python -m ruff format .
```

Если линтер продолжает сообщать об ошибках, исправьте их вручную и повторите
проверку. Набор правил включает ошибки синтаксиса, неиспользуемые импорты,
неопределённые имена, неоднозначные имена переменных и сортировку импортов
(`E4`, `E7`, `E9`, `F`, `I`). Длина строки для форматтера — 88 символов;
целевой синтаксис Python — 3.8, без обновления синтаксиса исходного ML-кода.

После установки pre-commit обе проверки автоматически запускаются перед
коммитом для добавленных в индекс Python-файлов. Если хук изменил файлы,
просмотрите изменения, снова выполните `git add` и повторите коммит.
Первая проверка скачивает окружение Ruff и требует доступа к сети.

GitHub Actions запускает те же хуки на всех файлах при push и открытии или
обновлении pull request. Если форматирование или линтинг не проходят,
проверка завершается с ошибкой.
